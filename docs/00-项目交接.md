# 校园二手交易系统｜项目交接

更新：2026-10-29。本文为新 Codex 会话的接手入口，仅描述当前实现。测试数字为最近一次验收结果，进程状态需接手时重新检查。

## 1. 项目目标

- 面向高校学生的 Spring Boot 毕业设计，优先保证 PC 端体验、交易闭环和答辩演示。
- 主流程：注册登录 → 发布闲置 → 管理员审核 → 浏览与咨询 → 下单约见 → 买家确认收货；支持取消待见面订单。
- 平台用于线下当面交易，不收款、不发货。在线支付、物流、退款、学校认证、邮件找回密码不属于已完成功能。学号是自行登记，确认收货只记录买家声明。
- 界面采用浅色侧边栏、黄黑品牌色、橙色价格和统一白色面板。遵循仓库 AGENTS.md：清理冗余 UI、布局不清时重构，兼顾用户、开发者与 AI Agent 体验，不破坏有效功能。
- 用户已明确跳过 Edge 实测与窄屏专项检查；后续优先桌面，不宣称完成全浏览器认证。

## 2. 技术架构

| 层级 | 当前实现 |
| --- | --- |
| 前端 | Vue 3、Vue Router 4、Pinia、Vite 7、Element Plus，JavaScript；Node 要求 ^20.19.0 或 >=22.12.0 |
| 后端 | Java 17、Spring Boot 3.1.2、Spring Security、BCrypt、JWT、MyBatis-Plus 3.5.3.1；包名 com.campus.secondhand |
| 数据库 | MySQL 8，库名 campus_secondhand；六张业务表与三张技术表均为 InnoDB，13 条外键，迁移版本 2 |
| 接口 | REST /api，响应 {code,message,data}，HTTP 状态对应错误语义；Vite 代理至后端 8080 |
| 身份 | JWT v3 绑定用户 ID、凭据标记与会话 ID；服务端校验账号、角色、有效期及撤销状态 |
| 消息与存储 | 消息轮询及游标分页；登录按“记住我”选择浏览器存储，草稿按账号隔离；当前未使用 Redis 缓存或 WebSocket |

请求路径：前端页面 → API 封装 → ApiGateFilter/CurrentUser → Controller 参数绑定 → ApplicationService 权限及业务编排 → 领域 Service 事务 → Repository（Mapper）→ MySQL → 统一响应 → 页面。Controller 不直接访问持久层，由 LayeringTest 检查。

必须保持的业务与数据约束：

- 商品状态：0 在售、1 已成交、2 已下架、3 待审核；待见面商品仍为 0，另有 pendingOrder。订单状态：0 待见面、3 已完成、4 已取消。
- 不能自购；仅买家确认完成；双方可取消待见面订单。交易写入统一走 OrderTradeService 的商品行锁、状态校验及事务，保留唯一约束，不能在 Controller 另写交易逻辑。
- 发布和消息重试复用 Idempotency-Key；修改提交内容后换新标识。业务写入与去重响应同事务保存。
- 个人发布、订单、收藏、收发消息及会话摘要读取 data.items，默认每页 20、最大 50；我的发布全量统计取 data.stats。聊天历史按消息 ID 游标每批最多 50 条。
- 新订单保存 snapshot_json；个人订单与结果页优先使用快照。历史失联订单保留 legacy_product_id，有效 product_id 可空，不伪造商品或快照。
- 既有业务表仍为 utf8_unicode_ci，没有统一转换 utf8mb4。结构变更同时维护 schema.sql 与 SchemaMigration，不能用 CREATE TABLE IF NOT EXISTS 代替旧表迁移。
